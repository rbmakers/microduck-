導論

0.1 一句話總結整個專案

在 GPU 上以物理模擬與 PPO 訓練單一策略網路，匯出成 ONNX，在機器人的 RK3566 上每 20 ms 推論一次，輸出各關節的目標角度，再由伺服韌體追蹤。能從模擬走到實機，靠的不只是 PPO，還有馬達模型（BAM）、感測誤差與延遲、reward 設計，以及訓練端與部署端一致的控制介面。

0.2 誰負責什麼

元件位置工作
microduck_rl訓練電腦任務、reward、PPO 訓練
MuJoCo / MuJoCo WarpCPU / GPU剛體、關節、接觸的物理計算
BAM模擬環境XL330 伺服馬達的電壓、反電動勢、摩擦模型

這是 model-free PPO：有物理模擬器，但不訓練神經網路動態模型。「有模擬器」不等於 model-based RL。

0.3 策略學的是什麼：單一網路，狀態 → 動作

整隻鴨不是「先定關鍵部位再依序給其他部位」，也不是「每個關節一個策略」。標準做法是一個網路每個控制時刻同時輸出所有關節目標，走路的週期性是 reward 逼出的湧現行為。腿式機器人關節高度耦合（髖怎麼動取決於膝、踝與重心），所以獨立策略通常行不通。

Observation61 維：角速度3、重力方向3、關節位置14、關節速度14、上次 action 14、速度命令3、頭頸命令4、身體命令65 維：q, q̇, command, command_velocity, previous_action
Action14 維，q_target = q_HOME + s·a（s=1.0）1 維，target = a·20°

上表 microduck 數字來自原始碼分析；4096×24 = 98,304 筆 transition／iteration，每環境只前進 24×0.02 = 0.48 s。

0.4 為什麼要做單關節實驗

整隻 microduck 的問題（模擬物理、馬達、延遲、PPO）都能在 head_yaw 一個關節上縮小重現。學習路線：

  1. 實驗2–4：不用 RL，理解 MuJoCo 模擬迴圈與位置致動器。
  2. 實驗5：把控制問題包成 Gymnasium 環境（obs / action / reward / reset）。
  3. 實驗6：PPO 學習追蹤，與手寫控制器比較。
  4. 實驗7–9：固定策略，測頻率、阻尼、延遲敏感度，也就是 sim-to-real 的縮影。

共同的時間結構：物理步 0.005 s（200 Hz），4 個物理步 = 1 次控制 dt = 0.02 s（50 Hz）；命令在 4 個物理步中保持不變（zero-order hold）。

方法論：每次只改一個因素；記錄命令與結果，兩者不相等；區分「分數變高」與「走得更好」。

單元 1｜實驗2 experiment2_stand.py：STAND 固定目標與自由機身

目標：能寫出基本 MuJoCo 模擬迴圈，並分清「載入模型」與「具備平衡能力」。

核心概念

  • 兩個物件：MjModel（結構與參數）、MjData（此刻狀態：qpos, qvel, ctrl, time）。
  • 索引不可假設相同：actuator id、joint id、jnt_qposadr（qpos 位置）、jnt_dofadr（qvel 位置）要各自用 mj_name2id 解析。free joint 的機身佔 qpos 7 格、qvel 6 格，所以關節索引與 id 通常不同。
  • STAND 是 keyframe，不是控制器：mj_resetDataKeyframe 只設初始狀態與初始 ctrl。之後固定 ctrl 不會修正平衡，機器人可能倒下。
  • qpos 與 ctrl 的差別：改 qpos 是直接搬狀態；改 ctrl 是下命令讓物理演化，才會出現加速、摩擦與追蹤誤差。

程式結構

model.opt.timestep = 0.005
loop:  data.ctrl[:] = home_ctrl          # 每 20 ms 一次命令
       for _ in range(4): mj_step(...)   # 4 個物理步
       mj_forward(...)                   # 刷新 xpos/xmat 後才記錄姿態
       寫 CSV（目標、實際、誤差、機身姿態、tilt、接觸數）
  • --fix-base：用 MjSpec.add_equality 加一個 world–trunk_base 的 weld 約束，隔離頭部伺服響應；這不是平衡控制。
  • 機身傾角：tilt = acos(R[2,2])，超過 45° 程式警告：之後資料含失衡影響。
  • 穩定性防護：非有限值檢查；data.time 倒退表示 MuJoCo 因發散重設，直接停止。
  • CSV 用 "x" 模式開檔，避免覆蓋既有實驗紀錄。

完成條件：能說出為何 nq ≠ nu，並解釋自由機身 RMSE 為何不能當伺服性能。

單元 2｜實驗3 experiment3_head_sine.py：正弦目標與追蹤誤差

目標：親眼看到「命令 ≠ 瞬間實際狀態」，並學會平滑地施加激勵。

程式與實驗2共用骨架，用 EXPERIMENT 常數切換是否加入正弦。命令：

envelope = 0.5 − 0.5·cos(π·min((t − settle)/ramp, 1))     # 餘弦漸增，0→1
ctrl_head = home_head + A · envelope · sin(2π f (t − settle))
  • 預設 A = 10°、f = 0.25 Hz、settle 2 s（先靜止）、ramp 2 s。
  • 餘弦包絡讓振幅起點與終點的斜率為零，避免一開始階躍衝擊造成暫態，汙染穩態量測。
  • 啟動前檢查 home ± A 是否超出關節範圍與 ctrl range。
  • 記錄量：目標 qcmd、實際 q、q̇、誤差 q_cmd − q、機身姿態。

建議的三個比較

  1. 低頻小角度：基本追蹤。
  2. 提高頻率：誤差與相位落後上升。
  3. 換增益或負載：見實驗4。

注意 CSV 的 time_s 是區間末，command_time_s 是命令產生時間，兩者差 20 ms；分析相位時要記得對齊。

單元 3｜實驗4 experiment4_actuator_kp.py：只改 head_yaw 的 Kp

目標：理解 MuJoCo position 致動器內部公式，並知道為何 Kp 要同時寫入兩個欄位。

推導：position 致動器

MuJoCo 的力為 F = gain·u + b0 + b1·length + b2·velocity。位置伺服的編譯結果是 gainprm[0] = kp、biasprm = [0, −kp, −kv]，即：

τ = kp·u − kp·q − kv·q̇ = kp(u − q) − kv·q̇

單關節的線性近似（J 為等效慣量、c 為關節 damping）：

J·q̈ + (c + kv)·q̇ + kp·q = kp·u
ωn = √(kp/J),   ζ = (c + kv) / (2√(kp·J))

所以 Kp 加倍：ωn 增為 √2 倍、ζ 降為 1/√2；頻寬變寬但更容易過衝。這也是為何只改 gainprm 而不改 biasprm[1] 是錯的：目標與實際角度的關係會變成 τ = kp'·u − kp·q，穩態會偏離目標（需要 q = kp'/kp·u），不是單純改 Kp。

程式重點（A–E 區段）

  • B 驗證 validate_position：只接受 gear=1、無 activation dynamics、fixed gain、affine bias、直接 hinge 傳動，且 biasprm[1] == −kp。避免把 general / motor 誤當位置控制器。
  • C 修改：gainprm[head,0] = biasprm[head,1]·(−1) = kp×scale，只改記憶體，不改 XML；Kv、damping、frictionloss、armature 皆保持原值。
  • E 診斷：每個物理步起點 mj_forward 後用 actuator length/velocity 重建 raw 力矩，與 actuator_force（限幅後）比較，得到區間內峰值力矩與「達到力矩界限」比例。
  • 穩態 RMSE 只計 command_time ≥ settle+ramp，排除暫態；不補償相位或 20 ms 時戳差。
  • 每次輸出 CSV 與同名 .parameters.json，保留完整配置以便重現。

預設固定機身、±10°、0.5 Hz、30 s。用法：--inspect-only 先看有效參數，再跑 --kp-scale 0.5 / 1 / 2。取樣是離散的，峰值不等於連續時間最大值。

單元 4｜實驗5 experiment5_head_env.py：MuJoCo → Gymnasium 環境

目標：把控制問題寫成 RL 任務，說清楚 obs、action、reward、terminated / truncated 的每個決定。

環境規格

項目內容
模型內嵌 XML：固定底座＋單一 head_yaw（range ±0.6 rad, damping .002, armature .001）；position kp=.25 kv=.02，ctrlrange ±20°，forcerange ±0.08 N·m
Actiona ∈ [−1,1]（shape (1,)），target = a·20°
Observation[q, q̇, command, command_velocity, previous_action]；前四項單位 rad, rad/s, rad, rad/s
命令c = A sin(2πft + φ₀)，A=10°，φ₀ 於 reset 隨機；c, ċ 一起提供相位資訊
Rewardexp(−(e/5°)²) − 0.02·(a − a_prev)²，e = q − c（步末）；沒有乘 dt
終止terminated：|q| > 30°（教學門檻）；truncated：steps ≥ max_steps（duration/dt）

設計要點

  • 為何 obs 要有 command_velocity 與 previous_action？只給位置命令 c，策略分不出命令正在往哪邊走（相位）；previous_action 讓策略能感知平滑懲罰與致動器狀態。
  • Reward 形狀：Gaussian，誤差 = 5° 時得 e−1 ≈ 0.37；誤差 0 得 1。平滑懲罰抑制 action 跳變，與 microduck 的 action rate 成本同一概念。
  • reset() 回傳 (obs, info)，step() 回傳 5 元組；環境不自動 reset，episode 結束後必須由呼叫端 reset。
  • 三種基準控制器（baseline_action，不是學出來的）：zero（目標 0）、direct（target = command）、feedback（target = c + 0.35(c−q) + 0.025(ċ−q̇)）。
  • 相同 seed 提供相同初始角度與相位，跨控制器公平比較。
  • check_env 驗證 Gymnasium 介面；observation_space 設無限界只是讓瞬態通過，不是正規化。

閱讀順序：XML → __init__ → reset → step → baseline_action → main。這個檔案是實驗6–9的共同基底，其 SHA256 會被記錄以確保比較的是同一環境。

單元 5｜實驗6 experiment6_ppo.py：用 PPO 學追蹤

目標：說明 PPO 一次訓練發生什麼，並公平評估學到的策略。

PPO 概念

δ_t = r_t + γ·V(s_{t+1}) − V(s_t)            # TD 誤差
Â_t = Σ_l (γλ)^l · δ_{t+l}                    # GAE，γ=.99, λ=.95
ρ_t = π_θ(a|o) / π_θold(a|o)
L_clip = E[ min(ρ_t·Â_t, clip(ρ_t, 1−ε, 1+ε)·Â_t) ]   # ε = 0.2

Critic 估計未來累積回報以計算 advantage；clipping 限制單次更新的策略改變量。

程式結構

  • [A] 建立未訓練的 actor/critic：MlpPolicy，net_arch = pi[64,64], vf[64,64]，Tanh；n_steps=1024, batch_size=64, n_epochs=10, lr=3e-4, ent_coef=0；單環境、CPU、無 observation/reward 正規化。
  • [B] model.learn()：蒐集 1024 步 rollout → GAE → 10 epochs、mini-batch 64 更新，重複。總步數向上取整到 1024 的倍數。
  • 訓練時 Gaussian 抽樣探索；評估時 deterministic=True（取均值，再由 SB3 截限）。
  • 存 initial.zip（未訓練）與 final.zip（SB3 ZIP，非 ONNX），checkpoint 每 10000 步。
  • 可重現性：config.json 記錄 seed、套件版本與 experiment5_head_env.py 的 SHA256；評估時不符就拒絕執行。

評估設計

五種控制器 zero / direct / feedback / initial / final，用完全相同的評估 seed（10000 起，與訓練 seed 42 分開）。指標：RMSE、2 秒後 RMSE（排除暫態）、mean reward、failed_episodes。initial 對 final 的比較才能證明改善來自學習，不是網路結構或環境本身。

實測結果（10 回合，seed 10000 起，0.5 Hz）

控制器RMSE (°)2 s 後 RMSE (°)mean reward失敗
zero7.0727.0710.3080

判讀

  • zero = A/√2：目標恆為 0 時誤差就是命令本身，10°/√2 = 7.07°，與實測吻合，是驗證環境與指標的理想錨點。
  • initial ≈ zero（7.05 vs 7.07）：未訓練網路輸出接近 0，證明 final 的改善來自學習，不是網路結構。
  • final 在暫態後誤差僅 0.047°，約為手寫 feedback（1.594°）的 1/34。但 feedback 的 0.35／0.025 係數只是示例、未經調校，此比值不代表 PPO 對最佳化 PD 的優勢。更公平的說法：PPO 自動找到遠高於範例的有效增益，且 mean reward 已達 0.9997（上限約 1）。
  • 全程 RMSE 0.071° 與 2 s 後 0.047° 的差來自開頭的初始偏移（±2°）暫態。
  • 單一訓練 seed、單一頻率，不能推論為一般性能。

此為教學用 SB3 PPO，不是 microduck 官方 mjlab／rsl_rl 訓練入口。指令：train --steps 100000 --out runs/head_ppo_01；evaluate --run … --episodes 10。

單元 6｜實驗7 experiment7_frequency_test.py：頻率泛化

目標：測試策略在訓練分布之外的行為，並理解 distribution shift 的內涵。

  • 固定 final.zip，命令頻率 0.25 / 0.5 / 0.75 / 1 Hz（訓練只用 0.5 Hz），每組 10 回合×10 s，前 2 s 視為暫態；不呼叫 learn。
  • 每個頻率下 direct / feedback / ppo 的命令完全相同（同 seed）。
  • 頻率改變的不只是「動作加快」：command_velocity = A·2πf·cos(·) 的幅度隨 f 線性放大（0.25→1 Hz 差 4 倍），obs 的第四維分布也跟著變。策略可能沒看過這種輸入範圍。
  • 輸出 summary.csv、episodes.csv、逐步 CSV、metadata.json；結束時再驗證模型檔 SHA256 未被改動。
  • action_at_limit_fraction 是施加 action 觸及 ±1 邊界的比例，不是力矩飽和比例。

實測結果（2 s 暫態後 RMSE，單位 °；失敗回合皆為 0）

頻率directfeedbackPPOPPO action 觸限比例
0.25 Hz1.0680.7880.0220.50%

判讀

  • 兩個手寫控制器的誤差幾乎與頻率成正比（direct 1.07→4.61，約 4.3 倍）：純相位落後的特徵，誤差幅度 ≈ 命令斜率 × 等效延遲。
  • PPO 在訓練頻率外仍平順退化：0.022→0.169°（約 7.7 倍），且在 1 Hz 時仍比 feedback 低約 20 倍。沒有崩潰，表示策略學到的是依 q, q̇, c, ċ 的局部映射，而不是死記 0.5 Hz 的波形。
  • 這仍在「同型態命令、僅頻率不同」的範圍內；1 Hz 與訓練頻率只差 2 倍，不代表能外插到更高頻或不同波形。
  • action 觸限比例僅 0.5–0.7%，PPO 沒有靠 bang-bang 換取精度。

結論範圍：這是單次訓練所得策略的敏感度測試，不是多個訓練 seed 的統計結論。RMSE 必須與 failed_episodes 一起判讀。

單元 7｜實驗8 experiment8_damping_test.py：被動黏滯阻尼敏感度

目標：理解模型參數誤差如何進入閉迴路，並避免混淆兩種「阻尼」。

  • 命令固定 0.5 Hz、±10°；阻尼倍率 0.5 / 1 / 2；只改 model.dof_damping[env.vid]。
  • 兩個不同來源：關節被動阻尼 c = 0.002（XML joint damping）；致動器 kv = 0.02（讀自 −biasprm[2]）。實際等效阻尼是 c + kv，寫入 parameters.csv 的 damping_plus_kv 欄。
  • 用實驗4的二階近似：ζ = (c + kv)/(2√(kp·J))。以教學模型估算（J ≈ 1.2×10⁻³ kg·m²，粗估）：ωn ≈ 14 rad/s（約 2.3 Hz），ζ ≈ 0.6。c 由 0.5× 到 2× 只讓 c+kv 從 0.021 變到 0.024（約 14% 範圍），因為 kv 遠大於 c，預期敏感度不大。
  • 每次建構環境都從原始值乘倍率，避免跨回合累乘；每回合 reset 後檢查阻尼未被還原，並 mj_forward。
  • 觀測不含阻尼值，策略只能靠原本 5 個觀測產生動作，因此這是固定參數測試，不是 domain randomization 訓練。

實測結果（2 s 暫態後 RMSE，單位 °；失敗回合皆為 0）

阻尼倍率（c）directfeedbackPPO
0.5×（0.001）2.0941.5320.0455
1×（0.002）2.1751.5940.0465
2×（0.004）2.3361.7160.0524

判讀

  • 如預期，敏感度小：阻尼放大 4 倍（0.5×→2×），direct 與 feedback 的誤差僅增約 12%，與 c+kv 只變約 14% 相符。方向也對：阻尼越大，響應越慢、相位落後越大、誤差越大。
  • PPO 的相對變化（+15%）看似最大，但絕對值只從 0.046° 到 0.052°，遠小於手寫控制器的誤差。
  • 這個結果不代表「PPO 對阻尼穩健」的一般結論：致動器 kv 主導了阻尼，測試範圍內模型幾乎沒被改變。若要檢驗參數穩健性，應改變 kp、kv 或慣量（例如頭部質量）。

對照 microduck：訓練時的 domain randomization 就是把摩擦、轉子慣性、電壓、負載壓降等參數在一個分布內隨機化，讓策略在訓練時就面對不確定性。

單元 8｜實驗9 experiment9_action_delay.py：action 純延遲

目標：量化延遲對閉迴路的影響，並看懂如何在不改原環境下擴充它（子類別加 FIFO）。

延遲模型

延遲 d 步：第 k 區間施加 u[k−d]，負索引為 0。DelayedHeadEnv 用 deque：

reset:  pending = [0.0]*d
step:   pending.append(sent);  applied = pending.popleft()   # d=0 時立即取出
        obs, ... = super().step(applied)
        obs[-1] = sent            # 策略仍看到「上一個送出」的 action
  • 默認 d = 0, 1, 2, 4 步，對應 0 / 20 / 40 / 80 ms。這是命令傳送延遲，不是感測延遲，也不改致動器內部 PD 更新頻率。
  • 策略看不到延遲值與佇列內容（部分可觀測），這是最貼近實機的情形。
  • 平滑懲罰針對相鄰「送出」action；另記 applied_smoothness_penalty。CSV 的 action / target_deg 是「已施加」語意，sent_action / sent_target_deg 是新送出值；d=0 時兩者相同。
  • 每次 reset 佇列與歷史清零，避免跨回合殘留。

預期量級與驗證

純延遲 τ 在頻率 f 造成相位落後 φ = 360°·f·τ：0.5 Hz 時 d=1 為 3.6°，d=4 為 14.4°。對振幅 A 的正弦，相位差 φ 造成的誤差幅度為 2A·sin(φ/2)，RMS 再除以 √2。

用 direct 檢驗這個模型：d=0 時 RMSE 2.175° 對應誤差幅度 3.08°，反推伺服本身的落後 φ₀ ≈ 17.7°；加上 d=4 的 14.4° 得 φ ≈ 32.1°，預測 RMSE = 2·10·sin(16.1°)/√2 ≈ 3.92°，實測 3.919°。純延遲加上伺服落後的相位相加，這個一階模型解釋了 direct 的行為。

判讀：全課最重要的一組結果

  • 手寫控制器平順退化，每步延遲約使誤差加 0.4–0.5°，符合相位模型。
  • PPO 在 20 ms 就從 0.047° 惡化到 2.5°（約 54 倍），action 觸限比例從 0.6% 跳到 60%。觸限比例是關鍵訊號：策略被推進飽和，行為接近 bang-bang。
  • d=2 的 PPO（6.60°）已接近「什麼都不做」的 zero 基準（7.07°）；d=4 為 12.09°，比 zero 更差，最大誤差達 23.1°（其餘控制器約 10.4°）。所有回合仍未被判失敗，只因 30° 終止門檻未被跨過，可見「未失敗」不是好指標。
  • 合理解釋（假設，未用逐步 CSV 驗證）：零延遲下訓練出的策略等效增益很高，才能達到 0.05°；延遲吃掉相位裕度後，高增益迴路變成持續振盪，直到 action 被截限，形成極限環。可用逐步 CSV 檢查 action 是否以固定週期正負交替來驗證。
  • 這是 sim-to-real 的典型失效：策略對「訓練時不存在的通訊延遲」極度敏感。對策是在訓練時隨機化延遲（microduck 的做法）、把最近數步 action 歷史放入觀測，或加大平滑懲罰以壓低增益。
  • 再次提醒：單一訓練 seed，且延遲對 PPO 是「未見過」的擾動；並不代表所有 RL 策略都如此脆弱。

這是測試單一已訓練模型，不是延遲補償訓練。microduck 訓練則把 IMU 派生觀測延遲 0–1 個控制週期、關節速度固定落後 1 週期，直接放入訓練隨機化。
